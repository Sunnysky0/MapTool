# 测试与性能

## 命令与当前边界

```bash
npm test                # Vitest 单元/集成测试
npm run test:e2e        # Playwright E2E
npm run build           # 源资产一致性 + TypeScript + Vite
npm run check           # typecheck + lint + test + build
```

Playwright 首次使用可能需要 `npx playwright install`。本页描述仓库中的测试意图与保护措施，不表示所有命令已在每个提交、浏览器或设备上运行；发布前应记录实际执行环境和结果。

## 已建立的自动化方向

Vitest 测试覆盖或计划覆盖以下纯函数/边界：

- SVG ↔ 艺术经纬标定往返、有限数和标定版本；
- 普通、全世界、跨日期变更线范围以及球面转换；
- 日期变更线切分、折线矩形裁剪；
- 源编译器固定哈希、path 全分类、装饰路径排除、transform、闭合/子路径元数据、LOD 密度、有限 little-endian 坐标和生成资产逐字节一致性；
- 六种投影的定义域、范围边界采样、等比 fit 与加密保护；
- 项目 JSON round-trip、严格拒绝损坏/未知字段/未知版本以及导入原子性；
- SVG 分组、元数据、透明背景和 PNG 尺寸/内存限制。

`e2e/map-workflow.spec.ts` 是初始 UI 主流程覆盖：按可访问名称定位控件，输入数值范围、切换投影、修改线宽，并在对应 UI 可用时解析 SVG/PNG/JSON 下载和回导 JSON。测试会显式跳过尚未组装进页面的可选阶段，而不是把缺失功能报告为成功覆盖。随着 UI 稳定，应把这些条件跳过逐步改成硬断言。

## 建议的发布验证矩阵

至少在 Chromium、Firefox、WebKit 中验证：

1. 应用及源资产加载，WebGL 可用和降级提示；
2. 欧洲局部、跨太平洋日期变更线、南极附近、全世界；
3. 数值输入与球面手柄使用同一范围状态，拖动不与 orbit 控制争夺指针；
4. 六种投影；墨卡托越界和 LAEA 反足点显示明确错误且不静默改范围；
5. SVG、透明 PNG、项目 JSON 下载；解析文件内容，不只等待 download 事件；
6. JSON 导入 round-trip 后文档字段一致，损坏文件不污染现有项目；
7. 键盘操作、可见焦点、表单 label、状态/错误 live region、窄屏抽屉及 `prefers-reduced-motion`。

视觉截图基线适合验证主界面、范围叠层和各投影类别，但应避免把抗锯齿或 GPU 差异误当几何回归。几何正确性优先使用结构、坐标或 RenderPlan hash 断言。

## 性能策略

- globe/detail 双 LOD：拖动和球面交互使用较轻数据，静止、构图或导出使用 detail；
- 球面线稿合批，逐点数据不进入 React 响应式状态；
- 投影工作放入 Worker 时使用 request/revision，取消或丢弃过期结果，防止旧预览倒灌；
- 交互预览可约 80–120 ms 防抖，停止后升级精度；
- 经纬裁剪在投影前完成，投影后按像素误差自适应加密，并设递归深度/点数上限和可见 warning；
- RenderPlan 可按源哈希、标定、范围、投影、画布和精度稳定缓存；
- PNG 在分配画布前检查正整数尺寸、每轴不超过 8192 px，且 `width × height × 4` 原始 RGBA 估算不超过 256 MiB；浏览器编码过程仍可能需要额外内存；
- 开发期应记录生成资产体积、顶点/输出点数、Worker 用时、主线程长任务、交互帧率和 4K 导出峰值内存。

这些是保护策略和目标，不是未经基准测量的性能承诺。出现退化时，优先调节 LOD、细分误差、批次与缓存，而不是在主线程上增加同步工作或静默降低最终导出正确性。
